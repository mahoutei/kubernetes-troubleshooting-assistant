# RAG plan audit — plan-vs-code drift and verified defects

- **Plan audited:** `docs/superpowers/plans/2026-10-29-rag-k8s-docs.md` (pre-reconciliation revision, committed at `6440aee`; line numbers below refer to that file version)
- **Implemented branch:** `feat/rag-eval`
- **Code baseline:** `ce0248b` (`feat(rag): add judge, eval runner, calibration, and ablation harness`) plus the inherited Tasks 1–8 code from `6440aee`, plus post-`ce0248b` commits `d209300` (certificate-test independence) and `93b4297` (batch embeddings + index-build phase logging), plus the final (uncommitted) change to `evals/run_eval.py` + `tests/test_eval_runner.py` that omits retrieval metrics from the unanswerable slice (they are undefined without gold sources)
- **Ledger rulings that override the plan:** `docs/superpowers/status/2026-10-29-rag-execution-ledger.md`
- **Audit type:** docs-only reconciliation. No file under `projects/**` was modified. Nothing was committed by this audit; the plan edits are the working-tree changes.
- **Method:** read every implemented source/test/eval file at `ce0248b` (and the post-baseline commits above), extracted every file-backed fenced block from the plan, diffed the two, then fixed the plan plus its narrative/commands. `git show 6440aee:...` supplied the pre-reconciliation line numbers.

## Verdict

**Plan stale vs code.** The plan was written before implementation and its embedded code blocks were design briefs, not mirrors. Every file-backed code block (42 of them) was replaced or re-authored against the implemented files at `ce0248b`; 41 match exactly and the one intended difference is an explanatory comment (see D2). A follow-up pass re-mirrored `tests/test_validate_questions.py` and `tests/test_eval_runner.py` after the Lead made the certificate tests certificate-state independent, and a later pass re-mirrored `src/rag/embed.py` and `scripts/build_index.py` after `93b4297` (batched embeddings, `show_progress` flag, index-build phase/elapsed logging), and a final pass re-mirrored `evals/run_eval.py` + `tests/test_eval_runner.py` for the unanswerable-slice aggregation rule. Every command/expected-count/interface statement that had drifted was corrected. The plan now describes the implemented contract: typed `Usage`, provider fallback and `LLMError`→503, document-level dedupe, `retrieve(..., top_k=20)`, the assessed CLI (split/mode/top-k/smoke/certification/artifacts), cross-family strict-JSON judge, calibration κ gate, the certification gate, and a Dockerfile/CI that can actually build.

One area remains forward-looking by necessity: **Task 11 (Docker/CI/HF Spaces)** describes target files that are not committed at `ce0248b`, because Docker is not installed on this machine and the image is built in CI/on the deploy host. Its commands were fixed statically but are not locally executable evidence.

## The uvicorn / import-time caveat (why it is in the plan now)

`src/rag/api.py` ends with:

```python
try:
    app = create_app(Settings.from_env())
except ValueError:
    app = None
```

`create_app` builds the default retriever unless one is injected: it loads the LanceDB index, the embedder, and the cross-encoder reranker. Consequences that the pre-fix plan omitted:

1. `uvicorn rag.api:app` triggers model loading at import, not at first request (≈13 min CPU cold start observed during Task 6). Always point it at a prepared index: `RAG_INDEX_DIR=data/index-smoke RAG_OFFLINE=1 uv run uvicorn rag.api:app --app-dir src --port 8000`.
2. If `Settings.from_env()` raises, the module-level `app` is `None` and uvicorn fails with an opaque import error — a missing index/key is a degraded `/health`, but a bad env is an import failure.
3. Test collection imports `rag.api`, so `tests/conftest.py` sets `RAG_INDEX_DIR` to a missing temp directory before any import; otherwise the suite would try to load a real index. The plan now ships that conftest block with the reason.

## Residual risk register

1. **Task 11 is unverified.** Docker/CI/README files do not exist at `ce0248b`; the plan's Dockerfile is a static design. Docker is not installed locally, so a CI build could reveal a layer/tag issue. Mitigation: build in CI or the deploy host and record the digest.
2. **Plan is a snapshot.** If `projects/**` changes after `93b4297` + the final uncommitted run_eval/test tweak, the plan can re-drift. Mitigation: re-run the extraction/diff check before publishing; the audit table gives the defects to re-check.
3. **Judge gate depends on human labels.** `evals/calibration.jsonl` is a 30-row template with `human_correct: null`; the κ gate cannot pass until a human fills it (and needs ≥ 20 pairs). Publication stays blocked by design.
4. **Certification is a field-presence gate.** `--require-certified` proves Reviewer/Date/Notes are non-blank, not that the review happened. The social gate remains.
5. **Free-tier cost is nominal.** `billed_usd`/`cost_usd_per_1k` are pinned to 0.0 with a note; token totals are recorded, but a future paid tier needs a price table before those numbers mean anything.
6. **p95 over 30 questions is coarse** and nearest-rank; report it with n and do not over-interpret single-run differences.
7. **Document-level recall can hide chunk ranking issues**; pair it with MRR/nDCG (kept) and per-slice numbers, and treat citation metrics separately.
8. **Dense-only depth ceiling** depends on `top_k_dense ≥ eval top_k`; keep the config invariant or fail loudly if `top_k_dense < 20`.
9. **Import-time eager loading** still costs ~13 minutes on a cold CPU when an index exists. The plan documents it; a lazy factory is a future code task, not a docs fix.
10. **Judge/provider availability:** cross-family judging needs `GEMINI_API_KEY`; generation needs `GROQ_API_KEY` (fallback optional). Without keys, generation/evals fail closed (503 / `--judge` error) rather than silently scoring.
11. **Certificate-test fragility — resolved post-baseline, no residual risk.** The two tests that asserted against the committed blank `CERTIFICATION.md` now build temporary certificates: `test_validate_questions.py` uses a `_blank_cert(tmp_path)` helper for the unsigned/underscores cases, and `test_eval_runner.py::test_test_split_requires_certification` writes its own blank cert and passes `--certification`. They therefore pass regardless of whether the committed certificate is signed. The plan re-mirrors both files, and the obsolete caveats were removed from Task 8/9; counts stay 4 (gate tests) and 14 (judge+runner+calibration).
12. **Unanswerable slices omit retrieval scores by design.** `_aggregate` only emits retrieval metrics when the aggregated rows contain answerable questions, because unanswerable questions have no gold sources (scores are undefined, not zero). The `unanswerable` slice therefore reports `n`, latency, and `refusal_accuracy` only. Consumers (README tables, summarize output, slice comparisons) must not compare retrieval columns on that slice; `test_eval_runner` pins the absence with `assert "recall@10" not in payload["slices"]["unanswerable"]`.
