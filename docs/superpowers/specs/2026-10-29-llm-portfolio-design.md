# LLM Engineer Portfolio — Design Spec

**Date:** 2026-10-29
**Status:** Draft for review
**Target roles:** Applied AI / LLM Engineer
**Builder level:** Intermediate (Python + some ML; limited deployment experience)
**Time budget:** 2–4 weeks at 10–15 h/week (~40–60 h total)
**Cash budget:** Free tiers only (Groq/Gemini free APIs, HF Spaces, Colab/Kaggle free GPU)
**Repo:** `ML-Engineer-Projects-for-Employment` (public GitHub)

## 1. Goal and success criteria

Build a two-project portfolio that proves applied LLM engineering, not tutorial-following.

Success means:

1. Two self-contained projects, each with a README a hiring manager can skim in 2 minutes.
2. A deployed RAG demo with citations that works on a free tier.
3. A reproducible eval harness with published numbers, ablations, and judge–human agreement.
4. A fine-tuned model with a base-vs-tuned-vs-prompted free-tier API comparison and a model card on HF Hub.
5. Every number in a README can be regenerated by a documented command.
6. Interview-ready stories: why hybrid retrieval, why reranking, what the evals caught, what was cut.

Non-goals: tutorial clone, framework demo, maximising feature count.

## 2. Portfolio shape

| # | Project | Primary signal | Time |
|---|---|---|---|
| 1 | RAG over Kubernetes docs with serious evals | Retrieval, evaluation rigor, deployment | ~30 h |
| 2 | LoRA fine-tune for function calling | Training, structured output, cost/latency trade-offs | ~15 h |
| — | Portfolio polish | Communication, reproducibility | ~5 h |
| — | Buffer | Rate limits, failures, re-runs | ~10 h |

No shared package between projects. Duplication is cheaper than a premature abstraction.

## 3. Project 1 — RAG over Kubernetes docs

### 3.1 Goal

Answer Kubernetes documentation questions with verifiable citations and publish retrieval/generation evals that are honest, reproducible, and better than the existing same-corpus projects.

### 3.2 Corpus

- Source: `kubernetes/website` markdown from branch `release-1.34`, pinned to commit `47132eb5367cfdcba0a3b33a0b3ffc81185bd7e8`, downloaded as a tarball at build time.
- Include `content/en/docs/**` (concepts, tasks, tutorials, reference); exclude blog, case studies, generated API reference.
- Preserve source path, heading, anchor URL, and docs version in every chunk.
- Pin the exact commit/tag in config; never scrape live docs at runtime.

### 3.3 Pipeline

1. **Ingest:** strip frontmatter and Hugo shortcodes; keep headings, code blocks, and lists.
2. **Chunk:** heading-aware, target ~500 tokens with ~15% overlap; never split a code block. Chunk config is parameterised for ablations (300/500/800).
3. **Embed:** `BAAI/bge-small-en-v1.5`, local CPU, normalised vectors.
4. **Index:** LanceDB vector table + BM25 (`rank_bm25`) keyword index, both built at image build time.
5. **Retrieve:** dense top-50 + BM25 top-50 → reciprocal rank fusion (k=60) → top-20 → cross-encoder rerank (`BAAI/bge-reranker-base`) → top-5 context.
6. **Generate:** free-tier LLM with a citation-enforcing prompt. Groq `openai/gpt-oss-120b` is primary and Gemini `gemini-2.5-flash` is the fallback on 429/5xx/timeouts; record the provider and model actually used. Refuse when retrieved context is insufficient. Return answer, citations, retrieval metadata, token usage, latency. A retired or unknown model ID must fail loudly (`404`/`model_not_found`), never fall through to an empty answer.
7. **Serve:** FastAPI `POST /ask`, `GET /health`, and a minimal HTML/JS page at `/`. One container, no Streamlit/Gradio dependency.
8. **Offline mode:** `RAG_OFFLINE=1` returns an extractive answer from the top chunk so tests and CI run without API keys.
9. **Deploy:** Docker image on HF Spaces (free CPU). Index is built into the image. Secrets via Space environment variables.

### 3.4 API contract

```json
POST /ask
{"question": "How does a PodDisruptionBudget work?"}

200 OK
{
  "answer": "... [1][2] ...",
  "citations": [
    {"id": 1, "url": "https://kubernetes.io/docs/...", "heading": "...", "chunk_id": "..."}
  ],
  "retrieval": {"dense_ms": 0, "bm25_ms": 0, "rerank_ms": 0, "chunks_used": 5},
  "usage": {"provider": "groq", "model": "openai/gpt-oss-120b", "prompt_tokens": 0, "completion_tokens": 0},
  "latency_ms": 0
}
```

`usage` always records provider + model + token counts for the call, including which provider answered when the fallback fires.

### 3.5 Eval design

**Gold set:** 60 questions, split 30 dev / 30 test. Slices:

- 20 single-hop factual
- 15 multi-hop / synthesis
- 15 troubleshooting / version-specific
- 10 unanswerable / out-of-scope

Each record:

```json
{
  "id": "q001",
  "split": "dev",
  "category": "single-hop",
  "question": "...",
  "reference_answer": "...",
  "gold_sources": [{"url": "...", "heading": "..."}],
  "required_facts": ["...", "..."]
}
```

Agents draft the set from the pinned docs; the human owner certifies every label. Dev is for iteration; test is run only for published results.

**Certification gate:** nothing is published until `evals/CERTIFICATION.md` is signed with a reviewer, ISO date, and notes, and the validator passes with `--require-certified`. The eval runner refuses a test-split publish without a signed certification record; agents draft, the human signs off.

**Retrieval metrics:** Recall@5/10/20, MRR@10, nDCG@10, per-slice breakdown.

**Generation metrics:**

- citation precision/recall against gold sources
- faithfulness: every claim supported by retrieved context
- required-fact coverage
- refusal accuracy on unanswerable questions

**Judge:** cross-family judge `gemini-2.5-flash` (never the generator model) with a fixed rubric; outputs cached on disk. Calibrate on 30 human-labelled samples and report Cohen's κ. If κ < 0.75, revise the rubric before trusting or publishing generation numbers.

**Ablations:** dense-only, hybrid, hybrid+rerank; chunk sizes 300/500/800. Minimum four configurations. Publish a table with quality, p95 latency, and cost per 1k questions, with per-slice retrieval metrics alongside the aggregate.

**CI:**

- unit tests for chunker, BM25, RRF, and metric math on tiny fixtures
- 15-question dev smoke eval with explicit thresholds, no API key required: the retrieval-only smoke requires `recall@10 ≥ 0.50` and `nDCG@10 ≥ 0.35`; a keyed generation smoke is additionally checked for ≥1 valid citation per answerable answer and zero unhandled 5xx. Below threshold fails the run. Thresholds are provisional until the first certified dev run.
- certification-gate test: an unsigned `CERTIFICATION.md` must be rejected
- cached judge fixtures for deterministic generation regression
- full 60-question eval is a documented manual command before releases

## 4. Project 2 — LoRA function-calling model

### 4.1 Goal

Fine-tune a small open model to emit reliable tool calls, then quantify the trade-off against the base model and a prompted free-tier API model (Groq `openai/gpt-oss-120b`, or Gemini `gemini-2.5-flash` if the Groq free tier is unavailable).

### 4.2 Data

- Dataset: `NousResearch/hermes-function-calling-v1` (Apache-2.0, public, no auth), using the 1,893 single-turn examples plus the first human→tool-call turn from the 5,209 cleaned Glaive examples (~7.1k raw rows). Pin the repo commit, each file's sha256, and row counts; write the parsed/split counts to a manifest instead of hardcoding them in prose.
- Dedupe exact duplicates plus near-identical rows (normalized user prompt + same target calls) before splitting. Residual limitation: case/whitespace/punctuation variants are caught, paraphrases are not; say so in the README and model card.
- Split 80/10/10 by normalized tool-schema hash (tool names + parameter paths/types; descriptions/defaults/examples ignored), not by row, so test tool schemas never appear in training. Record the actual counts in the manifest.
- Store only the dataset pin, manifest, and scripts in git; download data reproducibly and verify checksums.

### 4.3 Training

- Base: `Qwen/Qwen2.5-1.5B-Instruct` (Apache-2.0).
- Method: 4-bit QLoRA via Unsloth + TRL/PEFT; LoRA r=16, alpha=32, 1–2 epochs, max sequence length 2048.
- Hardware: Colab free T4 (fp16; bf16 disabled because the T4 does not support it); Kaggle GPU as fallback.
- Validation split is scored during training (`eval_strategy="steps"`, every 200 steps); `resume_from_checkpoint` survives a Colab disconnect.
- Determinism: fixed seed, pinned versions, config YAML, `reproduce.sh`.
- Artifacts: adapter and model card on HF Hub; training logs as CSV. Data, adapters, checkpoints, and logs are gitignored.

### 4.4 Evaluation

- ~710 held-out examples (exact count from the manifest).
- Metrics: tool-name accuracy, argument exact/F1, full-call exact match, JSON validity, p95 latency, and cost per 1k calls computed from recorded token usage. Each API call records provider, model, prompt tokens, and completion tokens; the cost basis is documented (free tier = `$0` token charges, local inference = no per-token spend).
- Comparisons: base model, LoRA adapter, prompted free-tier API (`openai/gpt-oss-120b`). If the Gemini fallback is used, label it; mixed-provider numbers are not directly comparable.
- Constrained JSON decoding with Outlines for local models; report the effect if time allows.
- Forgetting check: 200-example MMLU subsample before/after training with the chat template and an anchored letter parser; report the delta and 95% Wilson intervals.
- CI runs deterministic unit tests only (no model download, no API key). The full comparison is a documented manual command that needs a GPU and an API key.
- No live model demo required (1.5B on free CPU is too slow); optional GGUF/Ollama artifact if time remains.

## 6. Agentic execution workflow

**Phase 0 — Recon (parallel, ~1 h).** Three research subagents:

1. Tear down `kvsdileep/rag-for-engineers`, `Raudaschl/rag-fusion`, `Vikas9892/rag_evaluation`: architecture, eval approach, reusable pieces, licenses, weaknesses.
2. Tear down `deshpandetanmay/qlora-structured-extraction`, `aghasalim/lora-forgetting`: training/eval structure, pitfalls, reusable ideas.
3. Verify corpus/dataset/API feasibility: K8s docs paths and license, Hermes function-calling dataset schema/license, Groq/Gemini free-tier limits, and the currently served Groq model IDs (a retired ID such as the 2026-08-16 `llama-3.3-70b-versatile` shutdown must fail closed, not silently return empty output).

Deliverable: `docs/research/baselines.md` with a borrow / don’t-borrow table. Read-only; no code copied.

**Phase 1 — Plan.** `writing-plans` produces a task graph with dependencies, verification commands, and file ownership. Interfaces fixed first: `Chunk`, `RetrievalResult`, `Answer`, `EvalRecord`, extraction schema.

**Phase 2 — Build in waves.** Maximum 2–3 agents in parallel, on disjoint files/worktrees.

- Wave A: repo scaffold + CI; corpus ingest/chunker; eval gold-set draft; Hermes data prep.
- Wave B: index + hybrid retrieval + rerank; API/UI; fine-tune training run; eval harness.
- Wave C: ablations; judge calibration; HF Space deploy; HF Hub model card; READMEs; review pass.

**Phase 3 — Verification.** `verification-before-completion` on every claim; `requesting-code-review` subagent before merge; published numbers must come from a committed results file.

**Human-only gates:** certifying gold labels, approving published numbers, publishing anything public, handling secrets. Agents draft; the human signs off.

**Guardrails:** no code from unlicensed repos; `ATTRIBUTIONS.md` for adapted code; no agent invents benchmark numbers; CI must pass without API keys; model IDs live in provider config and a retired/unknown ID raises instead of degrading to empty predictions.

## 8. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Free-tier rate limits or API changes | caching, retries, provider fallback, offline CI |
| Model/API churn (a served model is retired or renamed) | provider config is the only source of model IDs; `404`/`model_not_found` fails loudly; Gemini fallback; re-run and relabel results if the primary is retired |
| LLM judge unreliable | human calibration, κ threshold, rubric revision |
| Judge self-preference / same-family bias | cross-family judge (`gemini-2.5-flash` scores Groq generations), fixed rubric, 30-sample human calibration |
| Eval set contaminated or too easy | draft from docs, human certification, dev/test split, unanswerable slice |
| Schema-hash split weakness | normalized names + parameter paths, independent leak test, manifest split counts; residual: enum/default/format changes are ignored and paraphrased duplicates are not deduped — document it rather than claim full control |
| Training-data drift | pinned dataset revision + sha256 + row counts + committed manifest |
| Colab session limits | small subset, checkpoint/resume, Kaggle fallback |
| HF Spaces cold starts/sleep | documented limitation, warm-up note |
| Scope creep | explicit out-of-scope list; YAGNI |
| Docs version drift | pinned tarball + commit hash |
| Licensing mistakes | attribution table, no unlicensed code, review gate; `LICENSE` is a human decision |

## 9. Out of scope

Auth, multi-user support, chat history, streaming, a vector-DB server, Kubernetes deployment, LangChain/LlamaIndex, agent frameworks, mobile UI, full observability stack (structured JSON logs only), a third project, and a blog series. Revisit only after both projects are published.

## 10. Assumptions

- The owner has free GitHub, Hugging Face, Groq/Gemini, and Colab (or Kaggle) accounts.
- The repo will be public.
- Demo links and HF Hub artifacts can be published.
- If any free tier disappears, the fallback is offline mode plus a recorded demo.

## 11. Open decisions resolved

- Corpus: Kubernetes docs.
- Fine-tune task: function calling on the Hermes/Glaive dataset.
- Eval tooling: custom Python harness, not RAGAS/promptfoo in the critical path.
- No third project; polish beats breadth.
