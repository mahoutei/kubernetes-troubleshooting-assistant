# LLM Engineer Portfolio — Design Spec

**Date:** 2026-10-29
**Status:** Draft for review
**Target roles:** Applied AI / LLM Engineer
**Builder level:** Intermediate (Python + some ML; limited deployment experience)
**Time budget:** 2–4 weeks at 10–15 h/week (~40–60 h total)
**Cash budget:** Free tiers only (Groq/Gemini free APIs, HF Spaces, Colab/Kaggle free GPU)
**Repo:** `ML-Engineer-Projects-for-Employment` (public GitHub)

## 1. Goal and success criteria

Build a two-project portfolio that proves applied LLM engineering, not tutorial-following.

Success means:

1. Two self-contained projects, each with a README a hiring manager can skim in 2 minutes.
2. A deployed RAG demo with citations that works on a free tier.
3. A reproducible eval harness with published numbers, ablations, and judge–human agreement.
4. A fine-tuned model with a base-vs-tuned-vs-prompted-70B comparison and a model card on HF Hub.
5. Every number in a README can be regenerated by a documented command.
6. Interview-ready stories: why hybrid retrieval, why reranking, what the evals caught, what was cut.

Non-goals: tutorial clone, framework demo, maximising feature count.

## 2. Portfolio shape

## 3. Project 1 — RAG over Kubernetes docs

### 3.1 Goal

Answer Kubernetes documentation questions with verifiable citations and publish retrieval/generation evals that are honest, reproducible, and better than the existing same-corpus projects.

### 3.2 Corpus

- Source: `kubernetes/website` markdown, pinned to a tagged release (v1.34 line), downloaded as a tarball at build time.
- Include `content/en/docs/**` (concepts, tasks, tutorials, reference); exclude blog, case studies, generated API reference.
- Preserve source path, heading, anchor URL, and docs version in every chunk.
- Pin the exact commit/tag in config; never scrape live docs at runtime.

### 3.3 Pipeline

1. **Ingest:** strip frontmatter and Hugo shortcodes; keep headings, code blocks, and lists.
2. **Chunk:** heading-aware, target ~500 tokens with ~15% overlap; never split a code block. Chunk config is parameterised for ablations (300/500/800).
3. **Embed:** `BAAI/bge-small-en-v1.5`, local CPU, normalised vectors.
4. **Index:** LanceDB vector table + `bm25s` keyword index, both built at Docker build time.
5. **Retrieve:** dense top-50 + BM25 top-50 → reciprocal rank fusion (k=60) → top-20 → cross-encoder rerank (`BAAI/bge-reranker-base`) → top-5 context.
6. **Generate:** free-tier LLM (Groq primary, Gemini fallback) with a citation-enforcing prompt. Refuse when retrieved context is insufficient. Return answer, citations, retrieval metadata, token usage, latency.
7. **Serve:** FastAPI `POST /ask`, `GET /health`, and a minimal HTML/JS page at `/`. One container, no Streamlit/Gradio dependency.
8. **Offline mode:** `RAG_OFFLINE=1` returns an extractive answer from the top chunk so tests and CI run without API keys.
9. **Deploy:** Docker image on HF Spaces (free CPU). Index is built into the image. Secrets via Space environment variables.

### 3.4 API contract

```json
POST /ask
{"question": "How does a PodDisruptionBudget work?"}

200 OK
{
  "answer": "... [1][2] ...",
  "citations": [
    {"id": 1, "url": "https://kubernetes.io/docs/...", "heading": "...", "chunk_id": "..."}
  ],
  "retrieval": {"dense_ms": 0, "bm25_ms": 0, "rerank_ms": 0, "chunks_used": 5},
  "usage": {"provider": "groq", "model": "...", "prompt_tokens": 0, "completion_tokens": 0},
  "latency_ms": 0
}
```

### 3.5 Eval design

**Gold set:** 60 questions, split 30 dev / 30 test. Slices:

- 20 single-hop factual
- 15 multi-hop / synthesis
- 15 troubleshooting / version-specific
- 10 unanswerable / out-of-scope

Each record:

```json
{
  "id": "q001",
  "split": "dev",
  "category": "single-hop",
  "question": "...",
  "reference_answer": "...",
  "gold_sources": [{"url": "...", "heading": "..."}],
  "required_facts": ["...", "..."]
}
```

Agents draft the set from the pinned docs; the human owner certifies every label. Dev is for iteration; test is run only for published results.

**Retrieval metrics:** Recall@5/10/20, MRR@10, nDCG@10, per-slice breakdown.

**Generation metrics:**

- citation precision/recall against gold sources
- faithfulness: every claim supported by retrieved context
- required-fact coverage
- refusal accuracy on unanswerable questions

**Judge:** free-tier 70B with a fixed rubric; outputs cached on disk. Calibrate on 30 human-labelled samples and report Cohen's κ. If κ < 0.75, revise the rubric before trusting or publishing generation numbers.

**Ablations:** dense-only, hybrid, hybrid+rerank; chunk sizes 300/500/800. Minimum four configurations. Publish a table with quality, p95 latency, and cost per 1k questions.

**CI:**

- unit tests for chunker, BM25, RRF, and metric math on tiny fixtures
- 15-question smoke eval with thresholds, no API key required
- cached judge fixtures for deterministic generation regression
- full 60-question eval is a documented manual command before releases

## 4. Project 2 — LoRA function-calling model

### 4.1 Goal

Fine-tune a small open model to emit reliable tool calls, then quantify the trade-off against the base model and a prompted 70B model.

### 4.2 Data

- Dataset: `Salesforce/xlam-function-calling-60k` (CC-BY-4.0, no auth).
- Subset: ~10k train / 500 val / 500 test, deduplicated.
- Split by tool-schema hash, not by row, so test tool sets never appear in training.
- Store only manifests and scripts in git; download data reproducibly.

### 4.3 Training

- Base: `Qwen/Qwen2.5-1.5B-Instruct` (Apache-2.0).
- Method: 4-bit QLoRA via Unsloth + TRL/PEFT; LoRA r=16, alpha=32, 1–2 epochs, max sequence length 2048.
- Hardware: Colab free T4; Kaggle GPU as fallback.
- Determinism: fixed seed, pinned versions, config YAML, `reproduce.sh`.
- Artifacts: adapter and model card on HF Hub; training logs as CSV.

### 4.4 Evaluation

- 500 held-out examples.
- Metrics: tool-name accuracy, argument exact/F1, full-call exact match, JSON validity, p95 latency, cost per 1k calls.
- Comparisons: base model, LoRA adapter, prompted 70B via free API.
- Constrained JSON decoding with Outlines for local models; report the effect if time allows.
- Forgetting check: 200-example general-capability set before/after training; report the delta.
- No live model demo required (1.5B on free CPU is too slow); optional GGUF/Ollama artifact if time remains.

## 6. Agentic execution workflow

**Phase 0 — Recon (parallel, ~1 h).** Three research subagents:

1. Tear down `kvsdileep/rag-for-engineers`, `Raudaschl/rag-fusion`, `Vikas9892/rag_evaluation`: architecture, eval approach, reusable pieces, licenses, weaknesses.
2. Tear down `deshpandetanmay/qlora-structured-extraction`, `aghasalim/lora-forgetting`: training/eval structure, pitfalls, reusable ideas.
3. Verify corpus/dataset/API feasibility: K8s docs paths and license, XLAM dataset schema/license, Groq/Gemini free-tier limits.

Deliverable: `docs/research/baselines.md` with a borrow / don’t-borrow table. Read-only; no code copied.

**Phase 1 — Plan.** `writing-plans` produces a task graph with dependencies, verification commands, and file ownership. Interfaces fixed first: `Chunk`, `RetrievalResult`, `Answer`, `EvalRecord`, extraction schema.

**Phase 2 — Build in waves.** Maximum 2–3 agents in parallel, on disjoint files/worktrees.

- Wave A: repo scaffold + CI; corpus ingest/chunker; eval gold-set draft; XLAM data prep.
- Wave B: index + hybrid retrieval + rerank; API/UI; fine-tune training run; eval harness.
- Wave C: ablations; judge calibration; HF Space deploy; HF Hub model card; READMEs; review pass.

**Phase 3 — Verification.** `verification-before-completion` on every claim; `requesting-code-review` subagent before merge; published numbers must come from a committed results file.

**Human-only gates:** certifying gold labels, approving published numbers, publishing anything public, handling secrets. Agents draft; the human signs off.

**Guardrails:** no code from unlicensed repos; `ATTRIBUTIONS.md` for adapted code; no agent invents benchmark numbers; CI must pass without API keys.

## 8. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Free-tier rate limits or API changes | caching, retries, provider fallback, offline CI |
| LLM judge unreliable | human calibration, κ threshold, rubric revision |
| Eval set contaminated or too easy | draft from docs, human certification, dev/test split, unanswerable slice |
| Colab session limits | small subset, checkpoint/resume, Kaggle fallback |
| HF Spaces cold starts/sleep | documented limitation, warm-up note |
| Scope creep | explicit out-of-scope list; YAGNI |
| Docs version drift | pinned tarball + commit hash |
| Licensing mistakes | attribution table, no unlicensed code, review gate |

## 9. Out of scope

Auth, multi-user support, chat history, streaming, a vector-DB server, Kubernetes deployment, LangChain/LlamaIndex, agent frameworks, mobile UI, full observability stack (structured JSON logs only), a third project, and a blog series. Revisit only after both projects are published.

## 10. Assumptions

- The owner has free GitHub, Hugging Face, Groq/Gemini, and Colab (or Kaggle) accounts.
- The repo will be public.
- Demo links and HF Hub artifacts can be published.
- If any free tier disappears, the fallback is offline mode plus a recorded demo.

## 11. Open decisions resolved

- Corpus: Kubernetes docs.
- Fine-tune task: function calling on XLAM.
- Eval tooling: custom Python harness, not RAGAS/promptfoo in the critical path.
- No third project; polish beats breadth.
