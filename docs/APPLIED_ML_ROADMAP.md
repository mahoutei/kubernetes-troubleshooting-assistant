# Applied ML delivery route

The selected primary track is enterprise AI for developer operations. The Kubernetes troubleshooting assistant is the flagship; the independent QLoRA notebook supports experimentation. This is a delivery plan, not a claim of paying customers, measured productivity gains or production readiness. [Current status](STATUS.md) records what is verified.

## Positioning

Build evidence-backed investigation support for Kubernetes teams and cloud consultancies. Demonstrate the full engineering loop: define the operational decision, establish a baseline, build and evaluate the system, deploy it reliably, measure actual use, and explain where it fails. Use the same case study for Applied AI Engineer / ML Engineer applications and for client discovery.

## Milestones in order

1. **Reliable flagship:** pass the remaining live-provider, human-review and Docker release gates. Publish a hosted URL only after verifying its health and incident workflow. Keep recorded demos clearly labeled and preserve the existing hosted generator path.
2. **Business evidence:** run the [client-pilot protocol](CLIENT_PILOT.md). Compare manual and assisted investigations on development incidents, retain private source observations, and report attempt duration alongside reviewed outcome quality. No productivity or revenue claim exists yet.
3. **Reviewable case study:** publish permitted measurements, evaluation design, architecture, operating costs actually observed, failure examples and a short walkthrough. Explain the choice of bounded retrieval/generation and why adapter routing is still experimental.
4. **Client discovery and bounded pilot:** validate the pain with prospective platform teams, agree data handling and acceptance criteria, and deliver a narrowly scoped investigation assistant. No cluster access or automated remediation is required. Contacting clients, buying hosting and making service commitments require separate user instructions.
5. **Second ML project:** after the flagship reaches demonstrable release quality, build a fraud/payment-risk decision system to show tabular ML, time-based validation, calibration and cost-sensitive thresholds. Public-data results and simulated cost assumptions must be labeled. Select the precise domain after reviewing target client or employer needs.

## Skills demonstrated by delivery

Python and SQL; API and data contracts; retrieval and evaluation; reproducibility; deployment and monitoring; leakage prevention and experimental design; and communication of business tradeoffs. Prioritize measured behavior over adding more agents, models or frameworks. The first milestone is an operational release, not another training run.

No salary or market-ranking assertion is made here. Target geography, work authorization, education and experience still need to be specified before tailoring applications or contract arrangements.
